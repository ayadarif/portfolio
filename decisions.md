# Decisions

- Next.js + TypeScript + Tailwind. One stack for the static portfolio page and the in-browser Experiment Readout.
- All site text in src/data/content.ts. Edit copy without touching layout code.
- No component library, CMS or animation library. Smallest thing that ships.
- Components are server components with no client JavaScript. Page is fully static, so it is fast and free to host.
- Public GitHub repo; secrets only in .env.local and Vercel env vars. .env.example is committed, real .env files are not.
- Deleted the default Next.js logo SVGs from public/. They were unused.
- Vercel Hobby (free) deploy straight from GitHub main. Every push redeploys; no separate build step to manage.
- Audited repo for secrets before treating it as public: only .env.example (no values) is tracked.
- Case study Results changed from one string to a list of bullets. Results are naturally several separate numbers; bullets scan faster.
- Added vitest as the only new dev dependency; bumped @types/node to ^22 because vitest's optional peer dependency refused ^20. Dev-only, no runtime effect.
- Stats module has zero runtime dependencies. Normal and chi-square tails are coded directly (erfc), so the tool runs in the browser with no stats library.
- Per-variant rate uses a Wilson CI (safe at low rates); the lift CI is unpooled; the p-value is the pooled z-test from the spec. At the 5% edge the CI and p can disagree slightly, so Ship/Don't ship need both.
- Power defaults to 80% (spec was silent). MDE uses a closed-form approximation, checked against an exact power solve in scripts/check_stats.py (about 2 to 4% apart).
- Verdict order: broken split, then below planned sample (even a scary early loss, because peeking inflates false alarms), then win, then loss, else no clear winner.
- Python check runs in a gitignored venv at scripts/.venv so system Python stays clean. Tests and the script share scripts/fixtures/datasets.json.
- Readout chart is hand-written SVG, not Recharts or Chart.js: one line, one band and a zero line is about 120 lines, adds no dependency, and I can explain every line.
- Chart reads its container width (ResizeObserver) instead of scaling a fixed viewBox, so axis text stays readable on a phone.
- Demos come from src/lib/demos.ts with a fixed seed; scripts/fixtures/datasets.json is generated from it so tests, the scipy check and the UI share one source.
- clean_win kept as originally written (scipy-checked test numbers depend on it); early_peek rebuilt as a novelty effect (lift near +40% on day 3, fading), 28 days, planned 40,000 per variant; broken_split regenerated with daily noise. All have unequal user totals.
- Underpowered check is skipped (shown grey, "Skipped") when no minimum lift is entered, rather than guessing a target.
- Business impact needs both monthly users and value per conversion, or neither. Half-filled would silently show nothing.
- vitest.config.ts added only to resolve the "@/" import alias in tests; scripts/ excluded from tsconfig so the Next build does not type-check the Node fixture script.
- Written readout is rules and templates first (src/lib/narrative.ts), so the tool works with no AI and never says "significant" unless p < alpha and the CI excludes zero. The AI layer can only reword it.
- Impact sentence is skipped when the verdict is "Fix the data first": numbers from a broken split should not get a dollar figure. Value is printed as a plain number, not a currency, because the form has no currency field.
- AI rewrite calls the Claude Messages API with plain fetch, no SDK: one request, zero new dependencies. Model id lives in one constant in src/lib/rewrite.ts.
- AI rewrite sends only verdict, computed numbers and the rule-based text, never the name, hypothesis or metric text. The key stays on the server.
- Validator rejects any "significan..." when the stats do not support it, even "not significant". Stricter than needed, but it matches the rule and a false reject just keeps the rule-based text.
- Validator allows a number only if it equals an input number rounded to the digits written. Heuristic, not proof; a rejected rewrite silently falls back, so the cost of a false reject is low.
- Rate limit on /api/rewrite is in memory (per server instance). Good enough to slow abuse for a portfolio; a real limit needs a shared store.
- No paid API. AI steps for future projects run offline in Claude Code; the site shows static results.
- The browser only calls /api/rewrite when the build flag NEXT_PUBLIC_REWRITE_ENABLED is "true" (unset by default). Why: the call sent a summary to our server on every readout even with the AI off, which contradicted "nothing is sent anywhere". Test: src/lib/rewrite-client.test.ts.
- The one exception is the Experiment Readout rewrite route (src/app/api/rewrite). It is dormant: off without a key and never run against the live API. Kept because it is built and tested; deleting it is a separate decision.
- Demo planned samples are written as literals in demos.ts (not computed) so scripts/write_fixtures.ts runs under plain Node with no tsconfig change; a test in readout.test.ts fails if any drifts from sampleSizePerVariant().
- Clean win target lift is 11%, not 10%: at 10% the formula needs 14,751 per variant but the data has about 14,130, which would flip the demo to Keep running.
- Feedback triage demo data: Hugging Face Federal-University-Lokoja/Bank-Review, Apache-2.0 per the dataset card, ungated, downloaded 2026-11-24 from https://huggingface.co/datasets/Federal-University-Lokoja/Bank-Review . Collected by the dataset authors, not us; credited on the page.
- Banks chosen by 2023 review count (UBA, Access, FBN), not the spec's default list (GTBank, Access, Zenith), because the spec says choose by count and those three rank higher. Year 2023, since 2024 has only a few reviews per bank.
- Sample is 1,000 reviews with seed 20261124, so the corpus is reproducible. The eval set (T3) is drawn from inside this corpus and held out.
- Personal data is stripped with regexes before any model call. Tested on made-up examples; it can miss things, and the page will not claim otherwise.
- Language mix is measured with a word-list heuristic, not a detector library, to avoid a dependency. Reported as rough.
- Eval set: 100 reviews from inside the corpus, seed 20261125, quota 30/15/15/15/25 for 1 to 5 stars (not proportional, so 2 and 3 star reviews are not too thin to measure). Consequence: agreement on the eval set is not a population estimate; say so on the page.
- The labelling sheet hides star rating and bank so they do not nudge Ayad's labels. Its order is shuffled.
- Codebook slugs are fixed and shared by the model and by Ayad; tie-break rules and severity anchors are in docs/triage-codebook.md. When torn on severity, label lower.
- Pipeline calls Claude Code headless (`claude -p`) per the spec: --safe-mode, no tools, no session saved, empty temp dir, stdin closed, JSON schema, model pinned to claude-sonnet-5-5. Output is read from the `structured_output` field. One smoke call showed an injected "ignore previous instructions" string inside <data> was ignored.
- Python standard library only (unittest, csv, subprocess). No jsonschema or pandas, so the tool has no install step. The code validates answers itself (ids match, slugs in the list, severity 1 to 3, themes use known ids).
- Reviews are fenced in <data> tags and the prompts say they are untrusted. Star ratings are not sent to the model, so labels come from the text alone.
- Priority = share x average severity x 100, ranked per bank. Praise and other are counted but never ranked. A review's second category counts as well as its first.
- Quotes are verified in code (verbatim, 200 characters or fewer, from a review labelled with that category, no fraud words, no titled names, no [PII] tags). security_fraud, praise and other get no excerpts.
- Dev run (50 reviews, 4 live calls, 0 failures) passed before any larger run.
